1. 시스템 개요 및 전체 아키텍처
================================================================================
개인투자자가 주식 시장에서 완전 자동화 매매(Full-Automated Trading)를 안정적으로
구동하기 위해서는 단순 단일 스크립트가 아닌, 각 역할이 분리된 모듈형 파이프라인
구조를 갖추어야 합니다.

[전체 데이터 및 주문 흐름]
+-----------------------------------------------------------------------------+
| 1. 장 전 스크리닝 (08:00 ~ 08:50)                                           |
|    - 전 종목(2,500+) -> 재무/기술적 필터링 -> 감시 유니버스(10~30종목) 압축 |
+-------------------------------------+---------------------------------------+
                                      |
                                      v
+-------------------------------------+---------------------------------------+
| 2. 실시간 시그널 엔진 (09:00 ~ 15:20)                                       |
|    - REST 폴링 / WebSocket 실시간 체결가 구독                              |
|    - 1분/3분/5분봉 보조지표(RSI, 이평선, 볼린저밴드, 거래대금) 실시간 계산   |
|    - 다중 팩터 스코어링 -> 매수/매도 시그널 생성                           |
+-------------------------------------+---------------------------------------+
                                      |
                                      v
+-------------------------------------+---------------------------------------+
| 3. 리스크 & 포지션 관리자 (Risk Manager)                                   |
|    - 현재 계좌 예수금 기반 1회 매수 비중 계산 (예: 종목당 예수금의 10%)     |
|    - 당일 계좌 최대 낙폭(MDD), 최대 보유 종목 수 제한 점검                  |
+-------------------------------------+---------------------------------------+
                                      |
                                      v
+-------------------------------------+---------------------------------------+
| 4. 주문 집행 및 예외 처리 (Order Executor)                                  |
|    - 증권사 REST API 주문 전송 (최우선 지정가 또는 시장가)                  |
|    - 미체결 주문 타임아웃 감시 -> 정정 또는 취소                            |
|    - 익절(Take-Profit), 손절(Stop-Loss), 트레일링 스탑 자동 추적            |
+-------------------------------------+---------------------------------------+
                                      |
                                      v
+-------------------------------------+---------------------------------------+
| 5. 모니터링 & 알림 (Notification)                                           |
|    - 텔레그램(Telegram) 봇 연동: 체결 내역, 일일 손익, 에러 로그 실시간 알림 |
+-----------------------------------------------------------------------------+

2. 증권사 API 비교 및 환경 선정 기준
================================================================================
국내 주식 자동매매에 주로 사용되는 증권사 API의 특성을 비교하여 목적에 맞는
플랫폼을 선택해야 합니다.

[1] 한국투자증권 (KIS Developers)
 - 통신 방식: REST API + WebSocket
 - 지원 OS: OS 무관 (Linux, macOS, Windows, Docker 컨테이너 지원)
 - 파이썬 환경: Python 64-bit 지원
 - 장점: 
   * 리눅스 기반 클라우드(AWS, GCP, VPS) 환경에 24시간 무중단 배포가 용이함.
   * OAuth 2.0 기반 토큰 인증 체계로 관리가 현대적임.
   * 국내주식 및 해외주식(미국 등) 인터페이스 규격이 통일되어 있음.
   * 공식 문서 및 GitHub 오픈소스 예제가 풍부함.
 - 단점: HTS 조건검색식 실시간 연동 기능은 지원하지 않음 (로직 직접 구현 필요).

[2] 키움증권 REST API
 - 통신 방식: REST API + WebSocket
 - 지원 OS: OS 무관 (현대적 웹 표준 프로토콜)
 - 파이썬 환경: Python 64-bit 지원
 - 특징: 키움증권 계좌를 유지하면서 리눅스 서버 배포를 원하는 경우 적합.

[3] 키움증권 OpenAPI+ (기존 버전)
 - 통신 방식: 32-bit OCX / COM 인터페이스
 - 지원 OS: Windows 전용 (Linux 미지원)
 - 파이썬 환경: Python 32-bit 필수 (PyQt5 기반 이벤트 루프 구동)
 - 장점: 영웅문 HTS에서 작성한 '조건검색식'을 실시간으로 연동하여 종목 수신 가능.
 - 단점: 로컬 윈도우 PC를 계속 켜두어야 하거나 비용이 높은 Windows VPS 필요.

▶ 추천 방향:
클라우드 서버(AWS EC2, Lightsail 등)에서 24시간 무중단 자동화를 목표로 한다면
OS 종속성이 없는 "한국투자증권 KIS Developers" 또는 "키움 REST API"를 추천합니다.

3. 4단계 자동매매 파이프라인 상세 설계
================================================================================

--------------------------------------------------------------------------------
3.1. [1단계] 장 전 종목 스크리닝 (유니버스 압축)
--------------------------------------------------------------------------------
국내 상장 종목은 2,500개가 넘기 때문에 장중에 전체 종목을 실시간으로 감시하면
증권사 초당 호출 제한(Rate Limit: 초당 5~20회)을 초과하게 됩니다. 따라서 매일
장 시작 전(08:00~08:50)에 거래 대상 종목을 10~30개로 압축해야 합니다.

* 스크리닝 필터링 기준 예시:
  1) 유동성 필터: 최근 20영업일 평균 거래대금 50억 원 이상 (환금성 확보)
  2) 시가총액 필터: 시가총액 1,000억 원 이상 (소형 작전주/이상 급등주 배제)
  3) 재무 건전성: 관리종목, 환기종목, 거래정지 종목, 자본잠식 종목 자동 제외
  4) 기술적 추세 필터:
     - 주가가 60일 이동평균선 위에 위치 (중기 상승 추세)
     - 최근 5일간 거래량이 직전 20일 평균 거래량 대비 150% 이상 증가
  5) 데이터 수집 도구: `pykrx`, `FinanceDataReader`, `OpenDART API`

--------------------------------------------------------------------------------
3.2. [2단계] 장중 실시간 시그널 엔진 (신호 포착)
--------------------------------------------------------------------------------
압축된 유니버스 종목들의 1분봉/3분봉 캔들과 실시간 체결가를 받아 진입 조건을 계산합니다.

* 다중 팩터 스코어링(Multi-Factor Scoring) 모델 예시:
  - Factor A: 당일 거래대금 유입 (장 개시 후 30분 내 전일 거래대금의 30% 돌파) -> [ +2점 ]
  - Factor B: 단기 이평선 정배열 (1분봉 기준 5선 > 20선 골든크로스) -> [ +1점 ]
  - Factor C: 모멘텀 지표 (RSI 14가 50 이상에서 우상향 돌파) -> [ +1점 ]
  - Factor D: 호가 체결강도 110% 이상 (매수세 우위) -> [ +1점 ]
  => 합산 점수가 4점 이상일 때 매수 시그널 발생

--------------------------------------------------------------------------------
3.3. [3단계] 포지션 사이징 & 리스크 관리 (자금 관리)
--------------------------------------------------------------------------------
수익보다 중요한 것은 원금 보존입니다. 리스크 엔진이 주문 직전에 진입 가능 여부를
판단합니다.

* 포지션 사이징 규칙:
  - 고정 비율 분할: 총 예수금의 10% 단위로 진입 (최대 동시 보유 5~8종목)
  - 1회 최대 주문 금액 상한선 설정 (예: 최대 300만 원)
* 청산 규칙 (Exit Strategy):
  - 손절선 (Stop-Loss): 매수가 대비 -2.0% 도달 시 전량 시장가 매도
  - 분할 익절 (Take-Profit): 매수가 대비 +3.0% 도달 시 보유 수량의 50% 분할 매도
  - 트레일링 스탑 (Trailing Stop): 최고점 대비 -1.5% 하락 시 나머지 50% 전량 청산
  - 타임컷 (Time-Cut): 진입 후 60분간 횡보 시 포지션 정리
* 계좌 킬스위치 (Kill-Switch):
  - 당일 누적 손실률이 계좌 원금의 -3% 도달 시 모든 보유 종목 전량 시장가 매도 후 당일 매매 강제 종료

--------------------------------------------------------------------------------
3.4. [4단계] 주문 집행 및 사후 관리 (미체결/슬리피지 제어)
--------------------------------------------------------------------------------
* 주문 방식:
  - 급격한 가격 변동 시 발생하는 슬리피지(Slippage)를 줄이기 위해 '최우선 매수호가 지정가' 또는 'IOC(Immediate-or-Cancel)' 주문 활용.
* 미체결 주문 처리:
  - 매수 주문 전송 후 30초 이내에 체결되지 않으면 주문을 취소하고 가격을 재계산하거나 매수 포기.
* 일괄 청산:
  - 15:15~15:20 사이에 오버나잇(Overnight) 리스크를 피하기 위해 당일 진입 포지션 전량 청산 (데이트레이딩 전략 기준).

[디렉토리 구조 설계]
auto_trading_system/

│   ├── screener.py          # 장 전 종목 스크리닝 모듈 (PyKrx 연동)
│   ├── strategy.py          # 기술 지표 계산 및 시그널 판별 엔진
│   ├── risk_manager.py      # 포지션 사이징, 손절/익절, 킬스위치 제어

│   └── db_handler.py        # 매매 기록 저장 (SQLite)

[의사 코드 흐름 (Pseudocode)]
```python
# main.py 실행 흐름
from core.screener import run_morning_screening
from core.kis_client import KISClient
from core.strategy import evaluate_signals
from core.risk_manager import RiskManager

def morning_job():
    global target_universe
    # 08:30 전 종목 대상 1차 유니버스 압축 (20종목)
    target_universe = run_morning_screening(min_trading_value=5000000000)

def trading_loop():
    # 09:00 ~ 15:15 1초/주기 감시
    for ticker in target_universe:
        ohlcv = kis.get_minute_chart(ticker)
        current_price = kis.get_current_price(ticker)
        
        # 1. 시그널 검증
        signal = evaluate_signals(ohlcv, current_price)
        
        # 2. 리스크 점검 및 주문 발주
        if signal == "BUY" and risk_manager.can_buy(ticker):
            qty = risk_manager.calculate_order_qty(current_price)
            order_res = kis.order_buy(ticker, qty)
            telegram.send_message(f"[매수 체결] {ticker} {qty}주 @ {current_price}원")
            
        # 3. 보유 종목 손절/익절/트레일링 스탑 감시
        risk_manager.check_exit_conditions(kis)
```

6. 인프라 구축, 운영 주의사항 및 리스크 방어책
================================================================================
1) 증권사 Rate Limit (초당 요청 제한) 방어:
   - 증권사 API는 통상 초당 5~20건의 요청 제한이 있습니다. 연속 호출 시 `time.sleep(0.05~0.2)`
     간격을 두거나 토큰 버킷(Token Bucket) 큐를 구현하여 차단을 방지해야 합니다.

2) OAuth 토큰 자동 갱신:
   - 한국투자증권 REST API 토큰은 24시간 유효합니다. 매일 08:00 스크리닝 직전에
     토큰을 자동 갱신하고 파일/캐시에 저장하여 재사용하도록 설계합니다.

3) 네트워크 단절 및 시스템 재시작 복구:
   - 인터넷 순시 단절 발생 시 자동 재접속(Retry) 로직을 넣고, 서버 재부팅 시
     현재 실제 증권사 잔고를 동기화하여 내부 상태와 일치시킵니다.

4) 모의투자(Paper Trading)를 통한 검증:
   - 전략 구현 후 즉시 실계좌에 투입하지 말고, 최소 2~4주간 모의투자 계좌에서
     장 시작(동시호가), 장중 변동성, 장 마감 시점의 예외 상황을 테스트합니다.
